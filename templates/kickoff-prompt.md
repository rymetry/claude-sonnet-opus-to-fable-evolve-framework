# 単発チャット用キックオフプロンプト(コピペ用)

プロジェクト機能を使わない単発の会話で、重要なタスクをSonnet 5に依頼するときの
テンプレートです。`{{ }}` を埋めて使ってください。

ポイントは3つ: (1) タスク・意図・制約を最初のメッセージに全部入れる(Sonnet 5は
小出しの指示より一括指定の方が性能・トークン効率とも良い)、(2) 成功基準を明示する、
(3) 検証を成果物の一部として要求する。

---

## タスク依頼テンプレート

```
次のタスクを、計画→実行→検証の流れで進めてください。

【タスク】
{{何をしてほしいか。動詞で明確に}}

【背景・意図】
{{なぜ必要か。この成果物が最終的にどう使われるか}}

【制約】
{{技術制約、トーン、分量、期限、やってはいけないこと}}

【成功基準】
{{「これを満たしていたら完璧」と言える条件を箇条書きで}}

【進め方】
1. まず計画: 成功基準の解釈、前提、ステップ分解を簡潔に示す。
   不明点があれば作業前にまとめて質問する。
2. 難所は段階的に深く推論してから書く。
3. 完成後、自分が書いたものではないつもりで敵対的にレビューする:
   正確性(重要な主張・計算をすべて再確認)、成功基準との照合、
   内部矛盾、エッジケース。見つけた問題は修正してから提出する。
4. 最後に: 確信がある点/不確実な点(とその検証方法)を明示する。
```

## 深掘りレビュー依頼テンプレート(既存の成果物に)

```
以下の{{コード/文書/分析}}を敵対的にレビューしてください。
あなたはこれを書いていない第三者で、問題を見つけることが仕事です。

要件: {{元の要件・成功基準}}

チェック観点: 正確性 / 要件との差分(暗黙に狭く解釈されていないか) /
内部整合性 / 壊れ方(どんな入力・変更で破綻するか) / 前提そのものへの反論

低確度・低重要度の指摘も含めて全部報告してください。
各指摘に 場所→問題→影響→確度→重大度 を付けること。
```

## 難問用テンプレート(分解が効かない深い推論に)

```
次の問題に本気で取り組んでください。もっともらしい一発回答は禁止です。

【問題】
{{問題の内容}}

【進め方】
1. まず問題を2〜3通りに再定式化し、簡易版を完全に解く。
   解く前に「正解が満たすべき受け入れ条件」を定義する。
2. 互いに独立な2〜3個のアプローチで別々に解く。
   各試行は直前のアプローチを忘れて、異なる角度から始めること。
3. 試行同士を突き合わせる。不一致箇所こそが本当の難所なので、
   自信の強さではなくケース分析か具体例の代入で決着させる。
4. 検証できる主張はすべて機械的に確認する(具体値の代入、小ケースの全列挙)。
5. 結論は「確立済み/おそらく正しい/未解決」に峻別して報告する。
   未解決には「何が分かれば決着するか」を添えること。
```
